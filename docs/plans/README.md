# Design history

These records preserve design decisions, migration steps, and validation at
specific milestones. Their API examples and test results are historical.
Use [implementation status](../status.md) and the current guides for supported
behavior.

| Record | Purpose |
| --- | --- |
| [Managed lifecycle feature description](managed-plugin-lifecycle/feature-description.md) | Requirements and proposed ownership/lifecycle design. |
| [Development plan](managed-plugin-lifecycle/development-plan.md) | Implementation phases and checkpoint notes. |
| [Checkpoint validation](managed-plugin-lifecycle/checkpoint-validation.md) | Evidence for the recorded native-lifecycle milestone. |

New proposals belong here until their scope is agreed and implemented. When a
proposal becomes current behavior, update its primary guide and link back to
the decision record rather than keeping two competing specifications.
